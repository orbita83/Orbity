# [RNF-0005] - Confiabilidade e integridade de dados

## 1. Contexto

O sistema deve executar operações de forma consistente e previsível, garantindo que os dados inseridos pelo estudante permaneçam íntegros e protegidos contra corrupção ou estados parciais.

## 2. Detalhamento

Operações que envolvem atualização de múltiplos registros (como concluir uma rotina com tarefas associadas ou finalizar uma sessão de foco) devem ser tratadas de maneira atômica e consistente: ou a operação é inteiramente concluída com êxito, ou o sistema preserva o estado anterior íntegro. Falhas de validação ou de gravação local devem ser tratadas sem travamento forçado do aplicativo (*crash*) e com preservação dos dados preenchidos no formulário.

## 3. Critérios de aceite

- **CA-01:** Falhas ocorridas durante qualquer etapa de gravação não devem deixar o sistema em estado parcialmente atualizado ou inconsistente.
- **CA-02:** Entradas inválidas nos formulários devem ser interceptadas antes da tentativa de persistência, mantendo o conteúdo já preenchido pelo estudante para evitar retrabalho de digitação.
- **CA-03:** O sistema deve apresentar mensagens claras de tratamento de erro e orientações caso uma operação não possa ser concluída, nunca apresentando confirmação de sucesso indevida.
- **CA-04:** Falhas inesperadas em módulos isolados não devem provocar o encerramento forçado do aplicativo, utilizando barreiras de contenção de erro (*error boundaries*) na interface.
